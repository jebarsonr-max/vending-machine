Engineering Motivation

Problem Statement & System Objectives

Why implement an automated vending controller in pure synchronous digital logic rather than standard microcontroller firmware?

✕

Firmware / MCU Pitfalls

  • ⚠️ Non-Deterministic Jitter: Software interrupt latency and OS scheduler jitter introduce microsecond timing anomalies during coin recognition.
  • ⚠️ Crash Vulnerability: Memory corruptions, stack overflows, and watchdog resets can cause coin loss or actuator burnouts.
  • ⚠️ High Static Power: General-purpose MCU instruction pipelines consume milliwatts of idle power compared to micropower CMOS gates.
✓

Digital Hardware Controller Advantage

  • ⚡ Nanosecond Determinism: Synchronous D-flip flop state memory transitions exactly on the clock edge with fixed setup/hold constraints.
  • 🛡️ Glitch-Free Moore Outputs: Actuator motors and coin solenoids fire strictly through registered states, eliminating output glitches.
  • 🔒 Tamper & EMI Resistance: Synthesized hardwired logic cannot be brute-force patched or corrupted by buffer injection attacks.

Binary vs One-Hot Synthesis Tradeoffs

State assignment directly impacts hardware resource utilization in CPLDs vs modern FPGAs.

Binary Encoding (3 FFs)
• States: 000, 001, 010, 011, 100
• Minimal flip-flop count ($\lceil \log_2(5) \rceil = 3$)
• Requires wider combinational decoding gates
• Ideal for ASIC/CPLD area-constrained designs
One-Hot Encoding (5 FFs)
• States: 00001, 00010, 00100, 01000, 10000
• Exactly 1 active high bit per state
• Minimal next-state logic (only 1-2 inputs/LUT)
• Preferred for FPGA architectures rich in registers

Mealy vs Moore Architectural Decision

Why does this project choose a Moore-dominated FSM with hybrid Mealy coin-rejection?

1. Glitch Immunity for Actuators (Moore): In Moore machines, outputs depend strictly on state registers $Q[2:0]$: Dispense_En = f(State). This guarantees 100% glitch-free pulses to electromechanical motors without risk of spurious firing during input signal transitions.

2. Instant Asynchronous Coin Reject (Mealy): If a customer inserts a coin while the machine is actively dispensing or returning change, a Mealy output path asserts Coin_Reject = f(State, Coin_Valid) immediately within the current clock cycle to prevent coin jams.

Logic Synthesis Pipeline

Step-by-Step Digital Design Process

From behavioral problem specification to gate-level schematic. Walk through state minimization, Karnaugh Map Boolean simplification, and synthesized equations.

Step 1: Formal System Specification

The controller operates in a synchronous 100MHz clock domain. The input subsystem samples coin sensors and item selection keys. The controller must track accumulated funds, verify whether the balance satisfies the selected item price, pulse the appropriate motor relay for exactly one cycle, and calculate change return using minimum coins.

Step 2: State Graph Formulation

Identified five unique functional operating conditions: IDLE (quiescent waiting state), ACCUMULATE (incrementing balance), SELECT (decoding item selection and comparing funds), DISPENSE (driving motor solenoids), and RETURN_CHANGE (executing change payout).

Step 3: State Minimization via Implication Table

An implication chart was evaluated to eliminate redundant states. Because each state has distinct output assertions (e.g., DISPENSE enables motors while RETURN_CHANGE enables coin ejectors), no two states exhibit equivalent output and next-state vectors. Hence, 5 states is the irreducible minimum.

✓ Minimization Result: 5 Unique States verified irreducible ($S_0 \neq S_1 \neq S_2 \neq S_3 \neq S_4$).

Step 4: State Assignment

State variables assigned: $Q_2, Q_1, Q_0$. States 101, 110, 111 are unused (treated as "Don't Cares" $X$ during Karnaugh map synthesis to aggressively minimize gate count).

Step 5: Karnaugh Map Simplification (Next-State Flip-Flop Inputs)
